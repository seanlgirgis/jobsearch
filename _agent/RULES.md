# Operating rules

## Workspace scope

This repository is Sean's job-market room: listings, intake, scoring, resumes,
covers, applications, gigs, and application interview preparation. ALOK
work-learning, courses, python_dsa/LeetCode, and local_memory work belong
elsewhere.

## Default behavior

- Work on one job or one pipeline step unless Sean explicitly asks for a broader
  audit, refactor, or cleanup.
- Before Python, run `. .\env_setter.ps1`.
- Use relative paths inside the repository.
- Read narrowly; do not enumerate all historical jobs, logs, captures, resumes,
  or career dumps for a normal task.
- Sean manages Git unless he explicitly delegates Git work.
- Do not make paid provider calls, change model settings, or touch external
  systems unless the request authorizes that action.

## Career truth

- Use `data/master/` and `data/master/bofa_stated_ai_work.md` for career facts,
  together with `docs/RUNTIME_PROFILE.md`.
- Current employer is LTIMindtree only; never name its client in public artifacts.
- CAPTAIN is research/investigation, never production, and its codename stays out
  of public documents.
- Do not present self-studied or beginner Databricks, Delta Lake, dbt, Snowflake,
  Unity Catalog, DLT, or Azure as production expertise.

## Pipeline safety

- Use `job-runner.ps1` and `docs/PIPELINE_OPERATOR.md` for new pipeline work.
- Gate before triage; triage before generation; inspect outputs before apply.
- A recommendation is not an application.
- Never submit to a website or mark a job applied without explicit confirmation.
- Use apply-only recording with the real method, date, and notes.
- An Apply filename is not proof of submission.

## Search-bot safety

- Read `search_bots/agent_work/README.md` before search-bot work.
- Never automate login, CAPTCHA, or Cloudflare verification.
- If Cloudflare appears, halt and leave the phrase incomplete for Sean.
- Treat local output and DNA as operational records; treat external handoff as a
  replica, not proof of application.
- Do not install unattended hosting until the approved scheduler replacement is
  implemented and tested.

## Change safety

- Preserve historical evidence and user edits.
- Prefer reversible documentation, labels, and compatibility redirects.
- Do not delete, bulk-move, reset, push, or rewrite history without explicit
  delegation.
- Keep credentials out of Markdown, JSON, YAML, logs, and generated artifacts.
